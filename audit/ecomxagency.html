Summary. This site is built well above the norm for its category. Heading structure is clean across 80 headings with zero level skips, all 23 buttons carry accessible names, all 182 links use descriptive text, and :focus-visible is used correctly in 30 places — that last one puts you ahead of most agency sites we scan. Findings

1

Accordion and drawer toggles never announce open/closed

Level A4.1.2 Name, Role, Value

What we found. 46 toggle elements (FAQ accordion, mobile menu drawer, collapsible blocks) — aria-expanded appears 0 times in the whole document. .accordion__plus-btn and .accordion__minus-btn are real <button> elements, so they receive keyboard focus, but a screen-reader user hears "Plus Icon, button" whether the panel is open or shut. Sighted keyboard users get the same ambiguity — the icon swaps visually, nothing is announced.

How to fix it. Add aria-expanded="false" to each toggle and flip it to "true" in the same JS that swaps the plus/minus icon. Add aria-controls="<panel-id>" pointing at the panel. Roughly one line per handler; no markup restructure. Alternatively replace the pair with native <details>/<summary>, which gets this for free.

Context. This is the only Level A failure found. It is also the cheapest to fix.

2

Carousel pagination dots have no focus indicator

Level AA2.4.7 Focus Visible

What we found. .slick-dots li button:focus, .slick-dots li button:hover { outline: none } — and unlike the site's other 17 outline:none rules, this one supplies no replacement (no box-shadow, no border, no background change). A keyboard user tabbing through the carousel sees the focus ring vanish entirely.

How to fix it. Give the focused state a visible indicator: .slick-dots li button:focus-visible{outline:2px solid currentColor;outline-offset:3px}. Keep :hover unstyled if the flat look matters — only :focus is the compliance issue.

Context. Note: the site handles this correctly in 17 of 19 places. This is an isolated slip, not a pattern.

3

Skip-link destination is focused invisibly

Level AA2.4.7 Focus Visible

What we found. .header *[tabindex="-1"]:focus { outline: none } with no replacement. Elements with tabindex="-1" inside the header are not tab-reachable, but they are the landing targets for the skip link and for JS focus management. The skip link itself is implemented correctly — the place it sends you to gives no confirmation you arrived.

How to fix it. Scope the rule so it does not swallow programmatic focus: .header *[tabindex="-1"]:focus-visible{outline:2px solid currentColor;outline-offset:2px}, or add a transient highlight on the target.

Context. Low user-facing frequency, but it undercuts an accessibility feature the site already paid to build.

4

Contact form result is never announced

Level AA4.1.3 Status Messages

What we found. One <form id="contact_form">, and aria-live appears 0 times site-wide. When the form succeeds or errors, the message is rendered visually only. A screen-reader user submits and hears nothing — no confirmation, no error.

How to fix it. Wrap the success/error container in <div role="status" aria-live="polite"> for confirmations and aria-live="assertive" for validation errors. The element must exist in the DOM before the message is injected, or the announcement does not fire.

5

Reduced-motion support is opt-in, so most animation escapes it

Level AAA2.3.3 Animation from Interactions

What we found. The @media (prefers-reduced-motion: reduce) block contains a single rule: .motion-reduce{transition:none!important;animation:none!important}. It only affects elements that already carry the .motion-reduce class. Meanwhile the stylesheet defines 7 keyframe animations — animateMenuOpen, star-animation-scale-one, star-animation-scale-two, star-animation-color, flickerAnimation, wave-animation, bounce — several running infinite: the guarantee-badge stars at 5s infinite, the loader dots at 1.5s infinite, and a tooltip at flickerAnimation 2s infinite.

How to fix it. Make the media query a blanket rule rather than a class opt-in: @media (prefers-reduced-motion:reduce){*,*::before,*::after{animation-duration:.01ms!important;animation-iteration-count:1!important;transition-duration:.01ms!important}}. Keep .motion-reduce for anything needing finer control.

Context. Checked for seizure risk (2.3.1) and it is clear: flickerAnimation cycles opacity 1→0→1 over 2s = 0.5 Hz, well under the 3 Hz threshold. The concern here is vestibular comfort, not photosensitivity.

6

Six external links open new tabs without warning

Level AAA3.2.5 Change on Request

What we found. 62 links carry target="_blank". 56 of them announce it via aria-label or title; 6 do not. Screen-reader and screen-magnifier users lose context when the tab changes with no notice.

How to fix it. Append the same pattern already used on the other 56 — e.g. aria-label="Instagram (opens in a new tab)". Also confirm rel="noopener" on all 62 (security, not accessibility).

Method

Live fetch of the rendered homepage (362,920 characters of HTML) and all seven linked stylesheets. Static analysis against WCAG 2.2 Level A, AA and AAA success criteria, plus AI-crawler and structured-data checks. Findings were then individually verified against source before inclusion — three candidate issues were discarded during that pass, including three inputs flagged as unlabelled that turned out to be type="hidden" and correctly exempt.

Limits, stated plainly. This is static analysis of one page. It cannot measure colour contrast ratios (requires computed rendering), keyboard traps inside JS-driven drawers (requires a live browser session), or screen-reader behaviour on dynamic content. A full engagement adds axe-core in a headless browser, manual keyboard traversal, and NVDA/VoiceOver spot checks across template types — cart, product, collection, checkout. The findings above are what static analysis can prove; they are not the complete picture, and no honest audit would claim otherwise.
